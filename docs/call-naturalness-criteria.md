# 영상통화 자연스러움 합격선

> 2026-10-23 확정 (대표). 팬이 "자연스럽다"고 느끼는 기준은 팬이 이미 아는 실제 영통팬싸다.
> 그래서 감이 아니라 실제 영통팬싸 295통을 잰 값을 합격선으로 쓴다.
> 아바타·화면·대화 흐름을 바꾸는 PR은 이 표의 숫자를 같은 방법으로 다시 재서 본문에 적는다.

## 1. 합격선

| 항목 | 합격선 | 근거 (실제 영통팬싸 295통) |
|---|---|---|
| 대화 방식 | 말로 주고받기 | 팬도 말로 한다 (영상에서 팬 말은 자막으로 달림) |
| 누군가 말하고 있는 시간 | 40% 이상 | 사분위 42% / 53% / 64% |
| 팬 말 끝 → 연습생 말 시작 | 1.4초 이내 | 말 사이 쉼 중앙값 1.38초 |
| 침묵 | 3초 넘기 전에 연습생이 채움 | 말 사이 쉼의 4분의 3이 2.86초 이내 |
| 얼굴 크기 | 화면 내용 영역의 8~17% | 중앙값 11.6% (사분위 8.0% / 11.6% / 16.7%) |
| 통화 시작 → 첫 얼굴 | 3초 이내 | 첫 얼굴 등장 사분위 0 / 0 / 3초 |

- 이 표도 가설이다. 실제 사람 3~5명이 걸어 보고 어디서 멈추는지 관찰해 확인한다.
- 원자료는 레포 밖에 있다 (원본 영상은 분석 후 삭제, 메타·분석 결과만 보관).

## 2. 재는 방법

| 항목 | 방법 |
|---|---|
| 실제 통화 | 말소리: Whisper 단어 시간으로 말 구간을 잡고 쉼 길이·말하는 시간 비율 계산. 얼굴: MediaPipe FaceLandmarker 눈썹~턱 상자 넓이 ÷ 검은 띠를 뺀 영상 내용 영역 |
| 우리 통화 | Playwright 헤드리스 Chromium. 가짜 마이크(질문 녹음 파일)로 말하고, 연습생 영상·음성을 MediaRecorder로 녹화. ffmpeg `silencedetect`(-35dB)로 연습생 말 구간을, 같은 방법으로 질문 녹음 파일에서 팬 말 구간을 잡아 녹화 시각으로 옮긴다. 말하는 시간 비율과 가장 긴 침묵은 **팬+연습생 합집합** 기준(실제 통화 기준과 같게). 대답 시작은 팬 말 끝 → 연습생 소리 시작. 얼굴은 같은 MediaPipe 모델로 통화 화면 캡처를 잰다 |
| 단계별 지연 | agent 로그의 `LAT` 줄 (`fancall/agent/latency_log.py`): end_of_turn, llm_first_token, tts_first_audio, avatar_playback |

## 3. 기록

| 날짜 | 구성 | 말하는 시간 | 대답 시작 | 가장 긴 침묵 | 얼굴 크기 | 첫 얼굴 |
|---|---|---|---|---|---|---|
| 2026-10-23 | 글자 입력, 먼저 말하기 없음 (Simli·ElevenLabs·Gemini 3.5 Flash) | 10% | 2.7~2.9초 (글자 전송 기준) | 29.2초 | 28% | 8~13초 (걸기 기준, 벨 포함) |
| 2026-10-23 | + 먼저 말하기 7초 (#34) | 33% | 같음 | 11.7초 | 28% | 같음 |
| 2026-10-23 | + 말로 대화, Flux 음성 인식, 먼저 말하기 1.5초 | 39% | 2.6~2.9초 | 10.6초 | 28% | 같음 |
| 2026-10-23 | + 말 끝 미리 감지(eager 0.4), Gemini 3.1 Flash Lite | — | 2.3~2.6초 | — | 28% | 같음 |
| 2026-10-23 | + 바로 맞장구(미리 만든 음성), 먼저 말하기 0.5초, 말 끝 대기 0.2초, 받을 때까지 벨 화면 (#37) · 2회 | 65~70% | 1.01~1.07초, 3번째 질문만 1.47~1.54초 | 2.7초 | 35% | 받은 뒤 0.5초 (벨 9.7~12.2초) |

- 마지막 줄부터 침묵·말하는 시간을 팬 말까지 넣어 잰다. 이전 줄은 팬이 말하는 시간도 침묵으로 셌다 (같은 녹화를 옛 방법으로 재면 가장 긴 침묵 3.6~3.7초).
- 3번째 질문이 느린 이유: 음성 인식 확정이 다른 질문(0.25~0.32초)보다 늦게 온다(0.63초). 말 끝 확정 기준 `FANCALL_STT_EOT_THRESHOLD` 0.6으로 한 번 재 보니 1.20~1.30초였지만, 도중에 ElevenLabs 무료 한도가 바닥나 그 녹화는 참고용이다.
- 맞장구를 음성 인식 '예비 확정'(preflight) 때 내는 방법도 해 봤다. 이어 오는 최종 확정이 맞장구를 끊고, 끊기지 않게 하면 LiveKit이 대답 자체를 건너뛰어 버렸다 (대답 시작 2.5초까지 늘어남). 되돌렸다.

남은 차이: 3번째 질문 대답 시작(1.4초 경계), 얼굴 크기(정사각 얼굴 아바타를 세로 화면에 확대, 상반신 아바타 필요), 벨 시간(에이전트·아바타 시작 10초 안팎).
